## 분석

1. **목적**: 숫자 비교만으로 순서를 고민하게 하는 퍼즐. 실패 → 즉시 재시작이 빠르고 가벼워야 한다.
2. **대상**: 휴대폰·PC로 짧게 즐기는 퍼즐 이용자, 마크 스킨·도트 꾸미기를 좋아하는 점프점프 이용자.
3. **핵심 작업**: 이어진 방 누르기 → 결과 확인 → (실패 시) 처음부터 / 되돌리기.
4. **정보 우선순위**: ① 내 숫자(머리 위 큰 칩 + 상태줄) ② 방 숫자·연결선 ③ 남은 되돌리기·이동 ④ 스테이지·시도.
5. **CTA**: 플레이 중 "처음부터"·"되돌리기", 결과 시트의 "다음 스테이지"/"처음부터 다시".
6. **컴포넌트**: 점프점프 Button·IconButton·Dialog·Toast·Switch·Segmented·InlineMessage·EmptyState·PixelIcon·ScreenLayout, 에디터(DotCanvas·Toolbar·Palette·ColorPicker) + 새 Board·NumberChip·Stars·SpriteImg·ResultSheet·ChestPicker.
7. **흐름**: 타이틀 → (이어하기 | 스테이지 선택 | 오늘의 도전) → 플레이 → 결과 시트 → 다음 스테이지. 타이틀 → 꾸미기 / 설정. 플레이 중 ⚙ → 설정 창(소리·모션).
8. **반응형**: 휴대폰은 보드 → 글줄 → 행동 순 세로. 1024px 이상은 보드 크게 + 오른쪽 행동·규칙 칸(sticky). 보드는 폭과 남은 높이 중 작은 쪽에 맞추고, 쓰지 않는 바깥 줄은 잘라낸다.
9. **접근성**: 방은 `button` + 이름(보이는 정보만), 로빙 tabindex + 방향키/Home, 결과는 `aria-live` 글줄 + 시트 제목, 갈 수 있는 방은 반투명 민트 바탕 + 굵은 연결선 + "갈 수 있음"(색만 아님. 2026-10-07 사용자 결정으로 점선·입체 표시를 바꿈), 포커스 링 유지, 44px 터치, 모션 줄이기(OS + 게임 설정).
10. **상태**: 로딩(스킨 받기·저장 중 버튼), 빈 상태(그림 없는 칸은 기본 그림), 오류(이미지 형식·크기·디코딩, 스킨 아이디·네트워크, 저장 실패, 저장소 사용 불가), 성공(저장 알림, 클리어 시트, 상자 결과 알림).
11. **일관성**: 점프점프 토큰(파스텔 채우기 + 잉크 외곽선 + 아래 두께), Jua 폰트, 도트 아이콘, 도트 무늬 배경을 그대로. 보드 색만 토큰 추가(`--board-*`, `--room-*`, `--chip-*`).

| 설정 | 효과음 · 모션 줄이기 · 진행 기록 지우기 · 그림 모두 기본으로 (확인창, 기본 포커스 취소) |

## 퍼즐 데이터·검증

- 스테이지 12개: 1~5는 손으로(규칙 소개), 6~12는 생성기로 찾은 뒤 검증. 6 상자 · 7 문 두 개 · 8 곱하기 물약 · 9 함정 · 10 이동 제한 + 시계 몬스터 · 11 숨은 숫자(되돌리기 1) · 12 전부(되돌리기 0).
- 솔버: 치운 방을 지나다니는 것을 묶어 "안 치운 방 하나와 부딪히기"를 한 행동으로 → 순환 없는 DFS + 메모. 상자는 모든 결과에서 깨야 하는 AND 노드.
- 테스트: 전 스테이지 풀이 가능, 4번부터 탐욕 전략 실패, 연결선 엇갈림 없음, 솔버 해답을 실제 규칙으로 따라가 보스 처치(상자 무작위).
